Citations that check themselves

Austin Wagner

Seventeen research wikis share one audit engine, and each declares which kind of proof its citations owe — a PDF hash, a captured-page hash, a resolving document query, or a git blob. A claim that cannot be checked that way fails the write.

Problem
Notes rot silently. A citation that pointed at something real when it was written is indistinguishable, later, from one that never did.
Result
Five source-contract kinds, one per class of evidence, dispatched by the wiki's own declaration — plus a separate guard that checks the container rather than the claims.
Scale
Papers, scraped technical sources, a civic document vault, nine codebase wikis, and four that pin nothing and say why.
Stack
TypeScript, PostgreSQL, hybrid dense + BM25 retrieval, MCP tools.
Where it runs
The same rules run on the filesystem, inside the database write transaction, and through a tool an agent calls.

One contract per kind of evidence

The insight is that "cite your source" means different things depending on what the source is, and a single rule for all of them either blocks honest writing or waves through unverifiable claims.

ContractWhat a page must pin
PDF archiveA local PDF, its SHA-256, and the vault document id — so the paper a claim rests on is the one still on disk
Captured HTMLThe saved page, its hash, its URL and the date captured — for technical sources that change under you
Document vaultA query that must resolve to at least one hit in the document store, re-checked rather than assumed
Code pathsSource paths plus each cited file's git blob hash, so editing the code invalidates the citation
External URLsNothing — and the contract says so explicitly, because those wikis are autobiographical or personal collections with no local archive to pin

The last row is the one worth arguing about. Declaring "these wikis pin nothing, and here is why" is a stronger position than quietly exempting them, because the exemption is then visible and has to be defended — and the rules that remain universal still apply, so every footnote must name a page, section, URL, line anchor or commit.

The rule that made this page possible

The code-paths contract records the git blob hash of every file a page cites. Change the file and the citation stops matching — the page is flagged as describing code that has moved, rather than continuing to read as current.

It is the same mechanism the article you are reading depends on. Every figure on this site is bound to a named wiki page and section, checked before the page can deploy. Writing these articles found four wiki pages carrying stale numbers, including one that described an actively running project as mothballed and one that said "eight commands" while naming seven against a real fifteen.

The audit checks the claims. Something else has to check the container — a separate guard verifies that each wiki's index counts match what is on disk, which is how a page moved between two wikis was caught leaving four numbers behind.

Why an agent needs this more than a person does

A person writing from a source they just read is unlikely to invent a figure. A language model asked to summarise a corpus will produce something plausible whether or not the corpus supports it, and plausible is the failure mode that survives review.

So the check is not advice, it is a gate: the same rules run in the write transaction, on the filesystem, and through the tool an agent calls, and a claim that fails them does not land. That is the difference between a research system an agent can use and one it can quietly corrupt.

Record

This page describes a system rather than a measurement, and it is documented in the codebase wiki that is itself under the code-paths contract — so the pages explaining the audit engine pin the blob hashes of the audit engine. The contract kinds and their per-kind rules are on wiki-check-audit-chain; the structural guard is on wiki-structure-guards.

Known limits. The rule count moves and is deliberately not quoted here; that page carries it with the date it was last re-read from the built module, and it had grown by eleven rules between two readings without the audit noticing — because a pin covering one file attests to one file. None of this checks whether a claim is true, only whether it is anchored to something a reader can open.
