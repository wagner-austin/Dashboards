A model that checks itself

Austin Wagner

I reverse-engineered the private protocol of an online game that publishes no documentation, then built an instrument that keeps proving the model is still right. It has since caught three of its own conclusions being wrong, including the ending of its best result.

Problem
No documentation, an encrypted wire, and a subtype byte that is scrambled per session so it cannot be trusted.
Result
32 message types decoded, each pinned to a signature, driving an autonomous bot that plays full sessions.
Best session
84 kills, 0 deaths, 149 minutes, unbroken. It ended because a fresh map held no affordable enemy.
Stack
Python, Playwright and the Chrome DevTools Protocol, a hierarchical state machine, a simulated server.
Gate
6,879 tests at full statement and branch coverage, no mocks, mutation testing on top.

The byte that cannot be trusted

Traffic is captured through the browser's own socket, because synthetic events do not work: commands have to travel the real connection. The codec is XOR with a static key and a per-session magic key, and I reversed both directions, encode and decode.

One container is the detail worth an interview. Its payloads cannot be identified by their subtype byte, because that byte is scrambled per session. So the decoder identifies them structurally, by length and byte pattern. The obvious approach fails, and it fails because of a property of the system rather than a mistake in the code.

Three conclusions the instrument refuted

The marathon session was real. Its ending was not: I had written that the bot ran out of opponents, and the operator said that was impossible because enemies respawn and there are always 27. He was right. The record showed every enemy rejected as stale map data, including one ten tiles away, because a map open had completed in 12 milliseconds by consuming an orphan flag from an earlier stalled open.

Then my explanation of that was refuted the same night. I had written that the connection was dying. It was not. The last frame the session ever received was the answer to its final question, arriving 5.7 seconds after dispatch and 3.7 seconds after the bot had already quit. What degraded was latency, not the wire.

The same disease then turned up a third time, in a different subsystem: every reported movement stall was fuel-starved latency crossing a fixed local deadline. The over-budget tail counts matched the stall counts exactly, 102 to 102. The stalls were never stalls.

One mechanism, three disguises: a slow answer crossing a fixed deadline, minting evidence that something downstream then believes.

Measurements that fail the build

Beliefs carry provenance and confidence, so every observed entity records where the knowledge came from. Validators price the model against the real capture archive, and every archived binary message must survive a decode and re-encode unchanged. Invariants raise where they are violated rather than after several observations of the consequence.

The part I would keep in any project: each machine-checked claim about the game's physics is one executable symbol, re-derived from the run archive on every build. A measured claim that stops holding fails the build instead of quietly rotting.

It earned that discipline. An optimisation probed ten clean runs out of ten, so I built and gated it; a second probe minutes later dropped 7 of 10, and it was reverted the same night, before it ever ran live. Round one alone would have shipped a change that cost time on every teleport.

Record

Every figure above is bound to a named section of the wiki page tankpitbot and checked mechanically before this page can deploy. The project keeps its own wiki of 6 hubs and 83 pages as the source of truth for wire protocol and mechanics, and its README defers to that wiki when the two disagree.

Known limits. The session figures are one session, recorded with its artifact id, not an average over many. The line counts move and are dated: re-measuring for this article found the probe suite had moved directories entirely, so the reproduction command recorded on the source page returned a count of zero rather than an error, which is the failure mode a dated figure is supposed to prevent and did.
